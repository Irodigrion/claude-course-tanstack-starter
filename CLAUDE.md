# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev            # dev server on http://localhost:3000
npm run build          # production build
npm run test           # vitest run (all tests)
npx vitest run tests/utils.test.ts      # single test file
npx vitest run -t "merges and dedup"    # single test by name
npm run check          # biome lint + format + organize imports, with --write
npm run lint           # biome lint only
npx tsc --noEmit       # type-check (no npm script for this)

npm run db:push        # sync src/db/schema.ts to the SQLite DB (no migration files)
npm run db:generate    # generate SQL migrations into ./drizzle
npm run db:migrate     # apply migrations
npm run db:studio      # Drizzle Studio
```

`DATABASE_URL` must be set (e.g. `DATABASE_URL="dev.db"` in `.env.local`); both `src/db/index.ts` and `drizzle.config.ts` depend on it, and `src/db/index.ts` throws at import time if it is missing. `.env*` files are denied for reading in `.claude/settings.json`.

## Architecture

TanStack Start (full-stack React 19 + SSR via Vite) with file-based TanStack Router, TanStack Query, Drizzle ORM on SQLite (`better-sqlite3`), Tailwind v4 and shadcn/ui.

- **Routing**: files in `src/routes/` are routes. `src/routeTree.gen.ts` is generated by the router Vite plugin on dev/build — never edit it by hand (it is excluded from Biome and read-only in VS Code). `src/routes/__root.tsx` is the HTML shell (`shellComponent`) wrapping every page with the Query provider, `Header`/`Footer`, and devtools.
- **Router + Query wiring**: `src/router.tsx` exports `getRouter()`, which injects `{ queryClient }` from `src/integrations/tanstack-query/root-provider.tsx` as router context (typed via `createRootRouteWithContext<MyRouterContext>` in `__root.tsx`). Loaders can access `context.queryClient` to prefetch.
- **Server code**: use `createServerFn` from `@tanstack/react-start` for server-side logic, or a route's `server.handlers` for API routes (see README). The Drizzle `db` in `src/db/index.ts` is server-only — import it only from server functions/handlers, never from client components.
- **Database**: schema lives in `src/db/schema.ts` (currently a sample `todos` table); `db` is created with the schema for relational queries.
- **Styling/theme**: `src/styles.css` holds Tailwind v4 config (`@import 'tailwindcss'`, no tailwind.config file), shadcn CSS variables, and custom app tokens (`--sea-ink`, `--lagoon`, etc.) plus utility classes like `island-shell`, `page-wrap`. Dark mode is class-based (`.dark` on `<html>`), set before hydration by `THEME_INIT_SCRIPT` in `__root.tsx` and toggled by `src/components/ThemeToggle.tsx` using `localStorage.theme` (`light|dark|auto`).
- **shadcn**: `components.json` targets `#/components/ui`; add components with `npx shadcn@latest add <name>`. Use `cn()` from `#/lib/utils` to merge classes.

## Conventions

- Import alias: `#/*` → `src/*` (defined in both `package.json` `imports` and `tsconfig.json`; `@/*` also works in TS).
- Biome: tab indentation, double quotes, recommended lint rules. Biome only covers `src/`, `tests/`, `.vscode/`, and `vite.config.ts`.
- Tests live in `tests/` (Vitest, jsdom + Testing Library available); there is no separate vitest config, so it uses `vite.config.ts`.


### Git
For Git commits follow the following rules:
- conventional commits format as described here https://www.conventionalcommits.org/en/v1.0.0/
- commit messages must be in English
- commit messages should be concise and descriptive of the changes made
- use appropriate commit type (e.g., feat, fix, docs, style, refactor, test, chore) to indicate the nature of the changes
- avoid using vague commit messages
